# CFRU への組み込み方

CFRU（Skeli 氏）系のビルドに F 方式の展開器を足し、LZ77 で読み込んでいる絵を F 方式に置き換えるための手順の概要です。
このリポジトリには CFRU のコードは入っていません。ファイル名・番地・関数名は、自分のビルドで確かめてください。

## 1. 展開器をビルドに入れる

1. `src/fcomp.c` と `src/fcomp.h` を CFRU の `src/` に置きます。`defines.h` が `u8 u16 u32 bool8 TRUE FALSE` を定義していれば、そのままコンパイルできます。
2. 圧縮器で作った `tables.s`（共通辞書とハフマンの表）を `assembly/` に置きます。シンボルは `gFDictSize` `gFDict` `gFLitTable` `gFLitSymbols` `gFLitFast` `gFDistTable` `gFDistSymbols` `gFDistFast`（`fcomp_cli.py` の `label` で変えられる）。
3. C 側で、関数の中に `struct FCompSet` を作って上のシンボルを入れます（`dictSize` は `.word` で置かれているので `gFDictSize` を読んで代入する。`const` の初期化子には書けない）。具体例は `examples/f_try_decode.c`。

### 書き換え可能な static は使えない

`.data` / `.bss` を持てない配置のビルドでは、展開器の状態を関数内の変数に置く必要があります。`src/fcomp.c` はそう書いてあります。

## 2. 展開の入口にフックする

ゲームの LZ77 展開は、ほぼすべてが BIOS の 2 つの入口（`LZ77UnCompWram` = `swi 0x11`、`LZ77UnCompVram` = `swi 0x12` を撃つ小さな Thumb 関数）を通ります。
その 2 つを、`examples/lz_dispatch.s` の振り分け役へ飛ばすように書き換えると、絵の読み込みコードを 1 つずつ直さなくて済みます。

- 振り分け役は、元データの**先頭 1 バイト**が F の印（例では 0x80）なら自前の展開器を、それ以外は今までどおり BIOS を呼びます。
- 印は、BIOS の圧縮形式（先頭が 0x10 / 0x20 / 0x30 / 0x50）とぶつからない値を選んでください。例の 0x80 はぶつかりません。
- 入口の関数の番地は ROM ごとに違います。逆アセンブルで `swi 0x11` / `swi 0x12` を撃つ関数を探し、先頭を「`r2` に WRAM/VRAM の別を入れて振り分け役へ分岐」に書き換えます。余っている領域（呼び元の無い関数など）にジャンプ先のアドレスを置く小さな踏み台を作る方法が使えます。
- 書き換えは ROM のビルド手順（リンカースクリプトの `.text` の配置、または後処理の Python）で行います。

### VRAM への展開

VRAM には 1 バイトの書き込みが効きません。`examples/f_try_decode.c` は VRAM のときだけ作業用の入れ物（`Malloc`）に展開してから 16 ビットずつ書きます。

### 不正なデータ

印が F のデータは、形が不正でも BIOS に渡さないでください（F のデータを LZ77 として読んで暴走するため）。例では `return 1`（何もしない）にしています。

## 3. 絵を F 方式にする

```
python tools/fcomp_cli.py pack out_dir sheet1.bin sheet2.bin ... --mark 0x80
```

- 入力は生の 4bpp シート（32 バイトの倍数）。出力は `out_dir/NNNN.fc`（印 + 生の大きさ 3 バイト + F のデータ）と `dict.bin` `tables.s` `tables.json`。
- 各 `.fc` を、元の LZ77 のデータの代わりに ROM へ置き、参照しているポインターを差し替えます。
- 辞書とハフマンの表は**圧縮に使ったシートの集合の統計**で決まります。後でシートを足す場合は、集合ごと作り直すか、辞書・表を固定したまま足してください（表は全記号に最低 1 回の出現を足して作ってあるので、新しいシートも符号化できます。縮み方は落ちます）。
- 圧縮器は純 Python です。シートが多いと時間がかかります（`max_chain` を `encode_all` の引数で下げると速くなりますが、縮み方は落ちます）。

## 4. 確認

- `python tests/test_roundtrip.py`: Python だけ。圧縮 → `decode()` で元に戻るかを自作の図形で確認。
- `python tests/host_c_check.py`: PC の C コンパイラ（clang / gcc）で `src/fcomp.c` をビルドし、圧縮器の出力を展開できるか確認。
- **実機（またはエミュレータ）での確認は、ここでは行っていません。** 組み込んだ ROM で、実際に絵が出る画面を見て確認してください。
- 遅さの目安: 展開は ROM 上の Thumb で動きます。大きなシートを 1 フレームの中で展開すると、読み込みの瞬間にもたつくことがあります。実機の画面で確かめてください。
